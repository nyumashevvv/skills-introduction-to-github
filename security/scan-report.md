## Исправлено

**CVE-2026-103922 (CVSS 9.3)** — в Capacitor 6.0–8.5.0 служебный адрес `/_capacitor_http_interceptor_` можно было открыть по чужой ссылке, и приложение загрузило бы страницу злоумышленника от своего имени (доступ к сохранениям и плагинам). В нашей игре ссылок нет, так что риск был низким, но исправление простое:

- `@capacitor/core`, `@capacitor/ios`, `@capacitor/cli`: 8.5.0 → **8.5.3**;
- `ios/App/CapApp-SPM/Package.swift` (нативная часть через Swift Package Manager): `capacitor-swift-pm` 8.5.0 → **8.5.3** (перегенерирован `npx cap sync ios`).

## Оставлено как есть

- `npm audit`: 3 уязвимости средней тяжести в `uuid` (GHSA-w5hq-g745-h8pq) по цепочке `@capacitor/cli → xcode → uuid`. Это инструмент сборки на компьютере разработчика, в приложение не попадает; срабатывает только при передаче своего буфера в `uuid`, чего CLI не делает. «Исправление» `npm audit fix --force` откатывает CLI на 8.4.3 — не применялось. Уйдёт с выходом нового `@capacitor/cli`.
- Semgrep `github-actions-mutable-action-tag` в `.github/workflows/` — файлы курса GitHub Skills, к игре не относятся.

## Ограничения

- MobSF смотрел исходники, а не собранный `.ipa`: бинарный анализ (флаги компиляции, PIE, ARC) требует сборки на Mac в Xcode. После сборки `.ipa` можно загрузить в MobSF ещё раз.
- Ручной ревью кода (claude-code-security-review) уязвимостей тоже не нашёл, см. предыдущий отчёт: единственное место — self-XSS при ручной правке собственного сохранения.
